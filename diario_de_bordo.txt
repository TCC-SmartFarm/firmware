=============================================================== 30/03/2026 ===============================================================

* Abandono do uso do conversor AD interno do ESP:
    - Usa menos bits que o conversor externo
    - Opera em uma faixa de tensão mais estreita (max 3V3, comparado aos 5V do ADS1115)

* Configuração do barramento I²C:
    - Pinos/Parâmetros compartilhados:
        PIN_NUM_I2C_SCL ---> Clock do BARRAMENTO
        PIN_NUM_I2C_SDA ---> Via de dados do BARRAMENTO
        I2C_MASTER_NUM  ---> Número da interface (o ESP32 tem 2 interfaces I²C)
    
    - Pinos/Parâmetros específicos de cada device:
        <device>_I2C_ADDRESS ---> Endereço do device específico ligado ao barramento

* CONFIG REGISTER do ADS1115:
    - Precisa receber como parâmetro de configuração uma variável de 16 bits
    - Conjuntos de bits entre os 16 disponíveis controlam partes diferentes envolvidas na leitura:

        Bit ---- Func ---------- Desc
        15 ----- OS ------------ Status de operação
        14-12 -- MUX[2:0] ------ Definição do canal
        11-9 --- PGA[2:0] ------ Ganho
        8 ------ MODE ---------- Modo de operação
        7-5 ---- DR[2:0] ------- Data Rate
        4 ------ COMP_MODE ----- Modo do Comparador
        3 ------ COMP_POL ------ Polaridade do comparador
        2 ------ COMP_LAT ------ Latching do comparador
        1-0 ---- COMP_QUE[2:0] - Fila do comparador

    - Define-se os bits para cada função e então faz-se a soma binária (OU - |) para chegar-se à
    palavra de configuração final desejada

    - Devide-se a palavra de configuração em 2 conjuntos de 8 bits a serem gravados no Config Register (endereço 0x01)
        O protocolo I²C funciona em pacotes de 8 bits por vez
        
* Após a leitura e conversão, o ADS1115 joga o resultado (16 bits) no Conversion Register localizado no endereço 0x00

* Ligação dos sensores analógicos:
    - Higrômetro e LDR
    - Leitura realizada no polo POSITIVO!
    - Ligação comum no GND e outro polo em cada canal específico do ADS1115
        Higrometro - A0
        LDR -------- A1

* O agrupamento de funcionalidades será atingido através de funções de orquestração definidas na própria main.c
    - Exemplo: função execute_readings() ---> Chama todas as funções individuais de leituras definidas nos controladores

* Fluxo de funcionamento | Máquina de Estados:

    1 - Wake up -> Verifica quem foi que acordou (botão de setup ou timer) para decidir se chama o menu de configuração ou faz leituras
    2 - Menu de configuração -> Guarda informações do usuário relevantes para a transmissão de dados no Non Volatile Storage (Cartão SD)
    3 - Setup do hardware -> Configuração dos barramento e dos periféricos
    4 - Ciclo de Coleta -> Chama as funções de leitura dos sensores para coletar os dados
    5 - Armazenamento -> Guarda os dados coletads no NVS
    6 - Transmissão -> Acorda o módulo LoRa para transmissão dos dados
    7 - Tear Down -> Desmontagem do NVS e desalocação dos barramentos
    8 - Deep Sleep -> Estado de baixo consumo de energia e definição do temporizador para acordar para o próximo ciclo

    ! A transição entre os estados e feita apenas pelos retornos das funções de orquestração uma vez que a lógica do programa é sequencial
